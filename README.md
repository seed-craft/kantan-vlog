# かんたんVlog（スマホ完結のシンプルVlog編集・試作）

スマホで撮った数本の動画を「選ぶ → 並べる・切る → 保存する」だけで1本にするWebアプリ。
動画・音声は端末の中だけで処理し、サーバーには送らない（ログイン・解析・広告・外部AIなし）。

## できること（v0.1）

| 機能 | 状態 |
|---|---|
| 複数の動画を選ぶ・サムネイル表示 | ✅ |
| 並べ替え（↑↓ボタン）・削除 | ✅ |
| 開始・終了位置の調整（スライダー＋「今の場面を…」ボタン） | ✅ |
| つなげてプレビュー | ✅（目安。iPhoneでは音量の反映なし） |
| 音声付きで書き出し → 共有メニュー／ファイル保存 | ✅ |
| 縦長（720×1280、標準）／横長（1280×720）を選ぶ | ✅ |
| 冒頭タイトル（最初の3秒、フェード。縦長ではSNSのボタンに隠れない高さ） | ✅ |
| BGM：内蔵のオリジナル曲4種（ほのぼの・わくわく・しっとり・キラキラ）をタップで試聴・選択 | ✅ |
| BGM：自分の音楽ファイル（ループ・フェードアウト） | ✅ |
| 元の音とBGMの音量 | ✅ |
| 進行表示・キャンセル・失敗しても編集内容を保持 | ✅ |

出力：縦長720×1280（標準）または横長1280×720・30fps・MP4（H.264＋AAC）。
向きの合わない動画は切り抜かず全体を収め、空いた所には同じ映像をぼかした背景を敷く（黒い帯にしない）。
MP4が作れないブラウザではWebM（VP9/VP8＋Opus）にし、画面に表示する。

## 起動

```bash
cd apps/vlog-editor
npm install
npm run dev        # 開発（同じWi-Fiのスマホから http://<PCのIP>:5173 で表示）
npm run build      # dist/ に静的ファイルを出力
npm run test:e2e   # build後に実行。Chromiumで実際に書き出して中身を検査
```

注意：WebCodecsは **HTTPS か localhost** でしか動かない。スマホから `http://192.168...` で開くと書き出しできない。
実機で試すときは、HTTPSで配信する（下の「公開」参照）か、PCのChromeのリモートデバッグ等を使う。

## 仕組み

- [Mediabunny](https://github.com/Vanilagy/mediabunny)（MPL-2.0、2026-10時点で活発に更新）で読み込み・デコード・MP4化。ブラウザ標準のWebCodecs（ハードウェアエンコーダ）を使うため、ffmpeg.wasmより軽く速い。
- AACをネイティブで作れないブラウザ（iOS 26より前のSafariなど）では、`@mediabunny/aac-encoder`（WASM）をそのときだけ読み込む。
- 内蔵BGMは `src/music.ts` がWeb Audioでその場で演奏して作る（音源ファイルなし・第三者の曲なし）。和音進行とリズムをコードで書いたオリジナル曲で、
  動画の長さぴったりに生成し、曲ごとの音量差が出ないよう平均音量でそろえる。権利処理が要らないので、家族・友だちへの共有にもSNSにも使える。
- 音声はOfflineAudioContextで「各クリップの音を順番に＋BGM」を1本に混ぜてから書き出す。つなぎ目には15msのフェード。
- 映像は30fpsの各時刻のフレームを取り出してキャンバスに描き（タイトルもここで描画）、エンコードする。
- 長さはフレーム数基準で決めるので、映像と音声の長さが必ず一致する。

## 確認済み／未確認

| 環境 | 結果 |
|---|---|
| デスクトップChromium（Playwright、Linux） | ✅ `npm run test:e2e` 全項目合格。H.264＋AAC（WASM）でMP4、9秒の動画を約5秒で書き出し |
| iPhone Safari | **未確認** |
| Android Chrome | **未確認** |
| iPhoneのHEVC（高効率）動画 | **未確認**（読めない場合は「互換性優先」で撮る案内を表示） |
| HDR（iPhoneの標準設定のHDR動画） | **未確認**（色が白っぽくなる可能性） |
| 長さ1分以上・5本以上・大きなファイル | **未確認** |

e2eで確かめていること：3本読み込み＋壊れたファイルの案内、切る、並べ替え、プレビュー、途中キャンセル後に編集が残る、
出力がH.264/AAC・標準で縦長720×1280・長さ9.0秒、ffmpegで全体をエラーなく再生、音の順番（880Hz→440Hz→無音）とカット位置、
縦長に横動画を入れたときのぼかし背景、タイトル描画、自分の曲のみ（元の音0%）、横長＋内蔵曲（元の音が主・曲も聞こえる）。

内蔵曲の聞こえ方・好みは**耳での確認が必要**（自動テストでは「鳴っている」ことしか確かめていない）。

## 制約（暫定）

- 合計3分・10本まで（スマホのメモリ保護のための暫定値。実機テストで見直す）
- 1本0.5秒未満には切れない
- 書き出し中は画面を開いたままにする（画面スリープは可能なら自動で防止）
- 完成動画は端末のメモリ上に作る（1分・720pで約10〜20MB想定）
- 今回作らないもの：字幕・テロップ（冒頭タイトル以外）、トランジション、AI編集、顔ぼかし、エフェクト、テンプレート、課金、アカウント、クラウド保存、SNS直接投稿、4K、長尺
- プレビューでは、向きの合わない動画は黒い帯で表示される（保存した動画ではぼかし背景になる）

## 実機で最初に試すこと（初心者向けチェック）

1. スマホで開き、説明なしで「動画を選ぶ → 保存」まで1本作れるか（迷った場所をメモ）
2. 内蔵曲を4つ試聴して、使いたいと思える曲があるか
3. 3本選んで、1本を短く切り、順番を入れ替えて保存できるか
4. 保存した動画が写真アプリで再生でき、音が出て、つなぎ目で音がずれないか
5. 横で撮った動画が切れずに入っているか
6. タイトルとBGMを付けて保存できるか
7. 書き出しにかかった時間（30秒の動画で何秒か）

## 公開（GitHub Pages）

`.github/workflows/vlog-editor-pages.yml` が、`main` に `apps/vlog-editor/` の変更が入ったとき（または手動実行）に
ビルドして GitHub Pages へ配信する。公開URLは `https://<owner>.github.io/<repo>/`。

最初に一度だけ本人がやること：

1. リポジトリの Settings → Pages → Build and deployment → Source を **GitHub Actions** にする
2. 非公開リポジトリのままPagesを使うには GitHub Pro 以上が必要（無料プランは公開リポジトリのみ）
3. Actions タブ → 「Deploy かんたんVlog to GitHub Pages」→ Run workflow（`main` で実行）

サイトは静的ファイルだけで、動画は各自の端末で処理されるため、利用者が増えても処理の費用は増えない。
費用が発生しうるのは、非公開リポジトリでPagesを使うためのGitHub Pro、独自ドメイン、Pagesの利用上限（転送量など）を超えた場合。

ホーム画面に追加すると、アプリのように全画面で開ける（manifest・アイコン付き。オフライン対応はしていない）。

## 似たツールとの位置づけ（参考）

本人が集めた調査（2026-11、未検証の二次情報を含む）では、個人製のブラウザ動画編集は
VibeCut・OsiVibe・Kite（タイムライン型・多機能）、CamCut（トリミング＋文字・PWA）、Clip JS（ffmpeg.wasm、スマホでは書き出しが遅め）など。
このアプリは **タイムラインを持たず「選ぶ→並べる・切る→保存」だけ** にし、WebCodecs（端末のハードウェア）で書き出す点で、
初心者・スマホ向けに最も手数が少ない側を狙う。
